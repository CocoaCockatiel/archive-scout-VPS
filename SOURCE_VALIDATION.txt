Archive Scout 1.0.3 source validation
Date: 2026-08-26

Release scope
- Final performance-focused release built on the complete 1.0.2 feature set and interface.
- Indexing: automatic broad/direct-media CDX traversal is resume-key-first, uses 100,000-row batches by default, preserves explicit paged compatibility mode, and converts unfinished 1.0.2 numbered queues without deleting already indexed captures.
- Acquisition resilience: large resume windows retain adaptive subdivision, saved queue state, shared Wayback pacing, finite pause budgets, and coordinated 429/503 recovery.
- Media: faster persistent external-embed discovery, exact-CDX resolution, URL-policy caching, fewer parser passes, batched database work, and the same row-scaled resume strategy as normal indexing.
- Scanning/analysis: lower-allocation keyword candidate selection, faster proximity scoring, batched analysis persistence, optimized first-appearance search, and no-op reuse of unchanged work.
- Research Intelligence: bulk metadata/relationship retrieval, SQL-side stale cleanup, incremental graph rebuilds, and fewer project-sized Python allocations.
- Database/reporting: faster compact CDX ingestion, index-assisted error lookup, additional safe indexes, throttled operation-progress persistence, and cheaper latest-report publication where hardlinks are supported.
- Existing AI relevance, bot/CLI automation, deterministic scoring, human review, reports, external media, project safety, and schema-v7 compatibility are preserved.

Indexing validation
- Automatic indexing selects resume-key traversal and does not depend on showNumPages/numbered-page enumeration.
- Automatic resume requests include urlkey in the CDX field list for reliable continuation and request 100,000 rows by default.
- Explicit paged strategy remains available for compatibility and diagnostics.
- An unfinished normal numbered queue with thousands of saved pages converts to resume traversal while retaining its date window and already committed captures.
- An unfinished direct-media numbered queue converts the same way.
- Automatic media indexing no longer turns automatic page grouping into pageSize=1.
- URLs containing spaces remain intact in line-oriented urlkey CDX responses and resume tokens are preserved.
- Untouched 1.0.2 50,000-row network defaults upgrade to 100,000 rows; deliberately customized values remain customized.
- Existing timeout subdivision, resume persistence, shared Wayback pacing, finite pause budgets, headerless 503 coordination, site-issue circuits, and interruption recovery remain covered by the full suite.

Performance-path validation
- Compact CDX tuples and mapping-form CDX rows persist with identical repository semantics.
- Repeated unchanged CDX rows remain no-op database writes.
- Keyword scoring retains exact aggregate score semantics in regression coverage while using lower-allocation candidate/proximity paths.
- External media discovery/retry, streamed media transfer, local rescan reuse, Research Intelligence, and analysis workflows remain covered by integration/unit tests.

Release limitations / remaining gates
- The offline benchmark is deterministic and does not claim a guaranteed live Internet Archive wall-clock speedup; Wayback server load and target shape remain external variables.
- A live Internet Archive large-site stress test was not performed in this validation environment.
- Native Windows, macOS, and Linux distributable binaries were not produced in this container because PyInstaller is not installed here.
- Build definitions were validated locally; GitHub Actions must produce and smoke-test the actual native GUI and ArchiveScoutCLI packages.
- Real Windows signing, macOS signing/notarization, and release-upload transactions were not performed.
- A live external AI-provider request was not performed because validation does not use user credentials.
- Publish tag v1.0.3 only after the GitHub Actions matrix and native package smoke tests pass on the exact patched release commit.
