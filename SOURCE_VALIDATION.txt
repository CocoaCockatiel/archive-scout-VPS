Archive Scout 1.0.6.6 source validation
Date: 2026-09-17

Release scope
- Replaces fragile automatic indexing recovery with a reference-style native Timemap JSON pipeline.
- Prevents one failed page from downgrading and replaying an otherwise successful year through broad resume-key windows.
- Adds live page-level progress during the existing 1,000-page rolling schedule.
- Applies the same correction to direct media indexing.
- Database schema remains version 8. No destructive project migration is introduced.

Reference comparison
- The attached Wayback downloader uses /web/timemap/json, pageSize=9, ten concurrent requests, an 80-requests/minute limiter, 1,000-page task groups, and five attempts per request.
- Archive Scout retains that proven acquisition envelope while preserving durable SQLite page checkpoints, shared 429/503 handling, pause/resume state, classified errors, and per-project capture metadata.
- Automatic numbered pages now use one native JSON endpoint and one representation per attempt. Generic resume-key CDX recovery remains separate.

Request behavior
- Timemap page counts omit the unused fl field.
- Timemap numbered pages request timestamp, original, mimetype, statuscode, digest, and length. The resume-only urlkey field is omitted.
- Page counts receive at least five native-JSON attempts for transient server/read failures before pagination fallback.
- Complete multi-backend connection failures return immediately to the operation-wide connection circuit rather than multiplying one DNS/proxy/TLS outage by five.
- A malformed or truncated numbered-page JSON body is rejected. It is never accepted as text and never triggers a text-format request for that page.

Failure isolation and resume
- Page failures remain in durable retry_pages/page_failures state while successful page rows and checkpoints commit atomically.
- One page receives five attempts without resetting the numbered-page plan.
- If an isolated page remains unavailable, Archive Scout pauses and saves only the exact failed page numbers. Resume continues those pages directly.
- Resume-key traversal remains the fallback when pagination is unsupported or the page-count operation remains unavailable after its retry budget.
- Existing v1.0.6.x numbered-page plans and completed index_pages/media_index_pages checkpoints remain compatible.

Progress behavior
- Main and direct-media indexing emit live progress during a 1,000-page scheduling block.
- Progress includes completed Timemap pages, total Timemap pages, pages completed in the current block, and capture counts.

Regression coverage
- Native Timemap page failures produce exactly one JSON request per attempt and no text request.
- Page counting receives five transient attempts.
- A persistent isolated page is attempted five times, successful sibling pages remain stored, no resume-key request occurs, and only the failed page is saved.
- Automatic paging uses only the native Timemap JSON endpoint.
- Page-count and numbered-page parameter sets omit unnecessary fields.
- Live page-progress events are emitted.
- Main and media indexing continue to use bounded parallel paging and durable completion checkpoints.

Local automated validation
- Full suite: 232 tests run, 231 passed, 1 environment skip, 0 failed.
- Python compileall passes for archive_scout, tests, and scripts.
- The built package reports Archive Scout 1.0.6.6.
- Offline 100,000-row benchmark completed with 100,000 inserts, zero duplicate work, zero HTTP attempts, and zero unchanged-row rewrites.
- Native multi-platform GitHub Actions/build smoke tests must still run on the exact release commit before publishing platform binaries.
