Archive Scout 1.0.5 source validation
Date: 2026-09-12

Release scope
- Fast-indexing and flat-media release built on Archive Scout 1.0.4 and database schema version 7.
- Automatic URL indexing now follows the reference downloader's Timemap acquisition model: Timemap JSON first, showNumPages once per saved window, fixed pageSize=9 in Auto mode, ten concurrent page workers, 0.75-second shared CDX request spacing (about 80 request starts/minute), and rolling queues of up to 1,000 numbered pages.
- Successful numbered pages are consumed and committed individually as they finish; one slow page does not create a ten-request batch barrier.
- Auto mode forces pageSize=9 even when an older saved queue carried another numbered-page block value. Explicit paged mode still permits custom page grouping.
- Timemap showNumPages parsing accepts the reference service's two-row JSON table shape as well as Archive Scout's existing compatibility shapes.
- Resume-key traversal remains available explicitly and remains the recovery fallback when Timemap pagination is unavailable, repeatedly pathological, or must be subdivided.
- Direct-media indexing uses the same Timemap-first page-count / pageSize=9 / ten-worker / 1,000-page pipeline in Auto mode.
- Media output is fixed to two flat directories only for v1.0.5-created output: media/images and media/videos. No host, timestamp, URL-path, fingerprint, or nested media directories are created by normal v1.0.5 media downloads or project merges.
- Media filenames use the raw final URL path component. Timestamp/database-id prefixes are removed and percent-escaped URL spelling is retained. Characters that cannot be represented as one portable Windows/macOS/Linux filename are percent-escaped rather than replaced with opaque names.
- Media replay acquisition follows the reference downloader's modifier logic: if_ for normal files and oe_ for SWF.
- Media replay keeps the v1.0.4 fast envelope of ten workers and 0.125-second shared request-start spacing (eight starts/second by default), guarantees at least five transient attempts, prioritizes known-small captures, and reuses an exact existing destination without another network request.
- Existing v1.0.4 text-format coverage, high-throughput text replay, native/fallback scan accelerators, index-only report repair, recovery controls, AI/Research Intelligence, review state, CLI automation, and project safety remain intact.

Indexing-performance validation
- Auto selects paged acquisition and places the Timemap JSON endpoint first while retaining CDX/Timemap fallback endpoints.
- Auto uses pageSize=9 and effective_page_workers(10, 9) resolves to ten concurrent numbered-page workers.
- A synthetic saved queue with page_blocks=50 is normalized to pageSize=9 when Auto mode resumes, preventing old settings from reducing the new fast pipeline's concurrency.
- The page scheduler selects up to 1,000 page numbers at a time and feeds them through the bounded ten-thread request pool; results are yielded as each future completes.
- The existing shared CDX limiter retains 0.75-second request-start spacing, matching the reference downloader's StrictLimiter(80/60) request envelope while preserving Archive Scout's process-wide host gate and recovery state.
- Direct-media indexing uses the same page-count, fixed grouping, concurrency, endpoint order, and rolling-queue architecture.
- Resume-key traversal and date-window subdivision remain intact as recovery mechanisms rather than the normal Auto acquisition path.

Media-layout and fetching validation
- A media run with no pending captures creates media/images and media/videos and no other child folders.
- Image and video path tests confirm one flat filename level beneath the respective type directory.
- URL path spelling is preserved: a URL ending in photo%20one.jpg is stored as media/images/photo%20one.jpg rather than being decoded, timestamped, hashed, or placed in a host/path tree.
- Normal replay URLs contain <timestamp>if_/ and SWF replay URLs contain <timestamp>oe_/.
- If the exact flat destination already exists, fetch_media hashes/reuses it and does not invoke network download, matching the reference downloader's preflight behavior.
- Download scheduling remains length-aware: known-size media is streamed in ascending length order before unknown-size rows.
- Media HTTP work remains bounded by the configured worker pool and shared request-start limiter; response bodies stream to .part files and are atomically promoted instead of being held as whole-project in-memory buffers.

Release limitations / remaining gates
- Offline/source validation does not claim a guaranteed live Internet Archive indexing or media completion rate. Wayback latency, server-side throttling, archive topology, capture size, and temporary service behavior remain external variables.
- A live Internet Archive large-site stress test was not performed in this validation environment. The release reproduces the reference downloader's request envelopes and Timemap queue architecture without bypassing Archive Scout's coordinated recovery/safety controls.
- The flat exact-URL-filename policy inherently means two different media URLs with the same final path filename map to the same destination. Matching the reference preflight behavior, the first exact destination already present is reused rather than renamed with an Archive Scout id/timestamp.
- Existing legacy media trees are not destructively flattened automatically; v1.0.5 stops creating deeper folders and all new/merged media destinations use only images/videos. This avoids silently deleting or overwriting older project files during upgrade.
- Native Windows, macOS, and Linux distributable binaries were not produced in this container because PyInstaller is not installed here.
- GitHub Actions must produce and smoke-test the actual native GUI and ArchiveScoutCLI packages on the release commit.
- Real Windows signing, macOS signing/notarization, and release-upload transactions were not performed.
- Publish tag v1.0.5 only after the GitHub Actions matrix and native package smoke tests pass on the exact patched release commit.
